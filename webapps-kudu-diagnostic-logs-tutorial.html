Enabling Advanced Diagnostic Logs and Accessing the Kudu Console

Beginner Kudu 6 min read

Nearly every Web Apps troubleshooting post on this site starts in the Kudu console. If you haven't turned on diagnostic logging yet, this gets you there — enabling the right log types and finding your way around Kudu before you actually need it during an incident.

Before you start
  • An existing App Service (Windows or Linux)
  • Contributor access on the App Service resource

  1. Enable Application Logging

    In the portal, go to your App Service → Monitoring → App Service logs. Turn on Application Logging (Filesystem for short-term, Blob Storage for retention beyond 12 hours), and set the level to at least Information for general use, or Verbose when actively debugging.

  2. Enable Web Server Logging

    In the same blade, turn on Web server logging (Filesystem or Storage). This captures raw HTTP request logs — status codes, response times, client IPs — separate from anything your application code logs itself.

  3. Enable Detailed Error Messages and Failed Request Tracing

    Still in App Service logs, turn on Detailed error messages and Failed request tracing. These capture the full IIS/pipeline trace for requests that fail server-side — invaluable for 500-level errors that don't show enough detail in the application log alone.

  4. Open the Kudu console

    Navigate to https://<your-app-name>.scm.azurewebsites.net. This is Kudu — the management/debug console that sits alongside every App Service. From here, Debug console → CMD (or Bash for Linux) gives you a live file system browser and terminal.

  5. Tail logs live

    Use Log stream (in the portal under Monitoring, or Kudu's own streaming logs endpoint) to watch application and web server logs in real time while reproducing an issue — far faster than downloading and re-reading log files after the fact.

    bash — stream logs via Azure CLI instead
    az webapp log tail --name your-app-name --resource-group your-rg

  6. Use Process Explorer for live diagnostics

    Kudu's Process Explorer tab (or Diagnose and solve problems → Diagnostic Tools in the portal) shows live CPU and memory per process, and lets you capture a memory dump on demand — exactly what the high CPU and memory leak posts on this site rely on.

Result: logging enabled, and a working path into Kudu for live log streaming, file browsing, and process-level diagnostics — the foundation nearly every other Web Apps troubleshooting post on this site builds on.
