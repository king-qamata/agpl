Hosting a Remote MCP Server on Azure Functions

Intermediate MCP · Flex Consumption 8 min read

The Model Context Protocol (MCP) gives AI agents and assistants a standard way to call tools hosted outside the model itself. Azure Functions now has a dedicated trigger type for this — McpToolTrigger — which turns individual functions into MCP tools an agent can discover and call remotely, without you standing up a custom protocol server yourself.

Before you start
  • Azure Developer CLI (azd) and Azure Functions Core Tools installed
  • Visual Studio Code with the Azure Functions and Azure Developer CLI extensions, if you want to verify locally with GitHub Copilot
  • An Azure subscription in a region that supports the Flex Consumption plan — this trigger type requires it

  1. Scaffold from the MCP server template

    Rather than building the protocol handling from scratch, start from Microsoft's template project for your language — it wires up the MCP trigger infrastructure for you.

    bash — example for the .NET template
    azd init --template remote-mcp-functions-dotnet -e mcpserver-dotnet

    Equivalent templates exist for Java, JavaScript, TypeScript, and Python.

  2. Define a tool with McpToolTrigger

    Each function decorated with the MCP tool trigger becomes a callable tool an agent can discover. The trigger handles exposing the tool's name, description, and typed parameters to any connecting MCP client.

    C# — a minimal tool
    [Function(nameof(SayHello))]
public string SayHello(
    [McpToolTrigger("hello", "Says hello back")] ToolInvocationContext context)
{
    return "Hello, I am an MCP Tool!";
}

  3. Add a tool with real bindings

    Tools aren't limited to returning static strings — they can use the same input/output bindings as any other function. A common pattern is a tool backed by Blob Storage for persistence, combining McpToolTrigger with a blob input or output binding just like the trigger types covered elsewhere on this site.

  4. Run and verify locally with GitHub Copilot

    Start the function app locally (Azurite emulating storage), then use the project's included .vscode/mcp.json configuration to point Copilot Chat's Agent mode at your local MCP endpoint. Enabling the tool and running a prompt that exercises it confirms the wiring works before you deploy anything.

  5. Deploy to a Flex Consumption function app

    Deploy using azd, which provisions a Flex Consumption plan following current secure-deployment defaults.

    Command palette (VS Code)
    Azure Developer CLI (azd): Package, Provision and Deploy (up)

  6. Connect a client to the remote server

    Built-in MCP authorization means the platform handles the OAuth handshake — connecting from VS Code or another MCP client triggers a normal Microsoft Entra sign-in flow rather than requiring you to build authentication into the function yourself.

Result: a set of custom tools, backed by real Azure bindings, discoverable and callable by any MCP-compatible AI client — running on serverless infrastructure with Entra-based auth handled by the platform rather than hand-rolled.
