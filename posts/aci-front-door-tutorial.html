Fronting Azure Container Instances with Azure Front Door

ACI Front Door 7 min read

As the ACI vs Web App vs ACA decision guide on this site notes, ACI has only limited custom domain and no automatic HTTPS support on its own. Putting Azure Front Door in front of a public container group closes that gap — managed TLS, a custom domain, and WAF protection, without changing anything about the container itself.

Before you start
  • An existing Container Instance with a public IP and a fully qualified domain name (FQDN) label set
  • A custom domain you control, if you want to attach one

  1. Ensure the container group has a stable FQDN

    Front Door needs a stable origin address — set a DNS name label on the container group so its address doesn't change across restarts.

    bash
    az container create \
  --resource-group rg-myapp \
  --name my-public-container \
  --image myregistry.azurecr.io/myapp:latest \
  --dns-name-label my-aci-app \
  --ports 80

  2. Create a Front Door profile

    Create a Front Door (Standard or Premium) profile and endpoint — Premium adds WAF and Private Link support if you need those.

  3. Add the container group as the origin

    Configure an origin group pointing at the container group's FQDN, with the health probe path matching an endpoint your container actually serves.

  4. Add a route

    Create a route mapping the Front Door endpoint to the origin group, with HTTPS redirect enabled so all traffic is forced to TLS at the Front Door edge — this is what gives the plain-HTTP container group effective HTTPS support.

  5. Attach a custom domain

    Add your custom domain to the Front Door endpoint and validate ownership via the required DNS record. Front Door manages certificate issuance and renewal for the domain automatically.

  6. Lock down direct access to the origin

    Without additional restriction, the container group is still reachable directly at its own FQDN over HTTP, bypassing Front Door's TLS and WAF entirely. For a genuinely secured setup, restrict the container's networking (via VNet deployment and Private Link, as covered in the VNet tutorial on this site) so Front Door is the only path in.

Result: a Container Instance served behind a custom domain with managed TLS and optional WAF — the practical way to close ACI's networking feature gap versus Web App for Containers or ACA, using Front Door as the layer that provides it.
