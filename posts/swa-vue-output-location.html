Vue on Static Web Apps: "App Not Found" from an output_location Mismatch

Vue Vite 5 min read
01SYMPTOM
02ENVIRONMENT
03DIAGNOSIS
04ROOT CAUSE
05FIX

01Symptom

The GitHub Actions workflow completes with a green checkmark and the Vue build itself succeeds locally, but the deployed Static Web App shows a generic "App not found" or blank page instead of the application — different from the deep-link 404 pattern covered in the routes.json trap post on this site, since here even the homepage doesn't load.

02Environment

  • Vue 3 app scaffolded with Vite (the current default tooling), deployed via the SWA GitHub Actions workflow
  • Workflow YAML generated by the SWA setup wizard or copied from an older Vue CLI-based example

03Diagnosis

Check the actual build output folder your local build produces against the output_location value in the workflow YAML. Vite's default build output is dist, but older Vue CLI-based tooling and some SWA quickstart templates assume different defaults — a mismatch here means SWA deploys an empty or wrong folder, not your actual built app.

bash — confirm the real output folder
npm run build
ls dist/   # Vite default — confirm this exists and has index.html
Common misdiagnosis: because the GitHub Actions run shows green, teams assume the build and deployment both succeeded correctly. A green check confirms the build command didn't error — it doesn't confirm SWA picked up files from the right folder afterward.

04Root Cause

The SWA GitHub Actions workflow's output_location field tells the deployment step which folder to actually upload as the site's static files. If this value doesn't match where your build tool actually writes output — a common mismatch when copying workflow YAML from an example using different tooling than your project — the action deploys whatever it finds at that path, which may be empty, stale, or simply the wrong content, all while the build step itself reports success.

05Fix

  • Set output_location to match your actual build tool's output — dist for a standard Vite-based Vue 3 project, confirmed against what npm run build actually produces locally.
  • Also verify app_location points at the folder containing your package.json, especially in a monorepo where the Vue app isn't at the repository root.
  • Re-run the deployment after correcting the YAML — this isn't something that resolves itself on the next unrelated push; the workflow file itself needs the fix.
Prevention tip: after any change to build tooling (migrating from Vue CLI to Vite, for example), explicitly re-verify the workflow YAML's app_location/output_location values rather than assuming they still match — build tool migrations are a common trigger for this exact mismatch.
