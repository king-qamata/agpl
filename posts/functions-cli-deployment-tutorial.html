Deploying Your First Azure Function with the Azure CLI

Beginner HTTP Trigger 6 min read

Before you can troubleshoot a Function App, you need one running. This walks through creating and deploying a minimal HTTP-triggered function using only the Azure CLI — no portal clicking required, which also makes it easy to script or repeat.

Before you start
  • Azure CLI installed and signed in (az login)
  • Azure Functions Core Tools installed locally
  • An active Azure subscription

  1. Scaffold a local function project

    Create a new project and add an HTTP-triggered function using Core Tools. This generates the local folder structure, host configuration, and a starter function.

    bash
    func init MyFunctionApp --worker-runtime dotnet
cd MyFunctionApp
func new --name HttpExample --template "HTTP trigger"

  2. Test it locally

    Run the function host locally and confirm you get a response before touching Azure at all — this saves a lot of time versus debugging a deployment issue that's actually a code issue.

    bash
    func start
# then in another terminal:
curl http://localhost:7071/api/HttpExample

  3. Create the supporting Azure resources

    A Function App needs a resource group, a storage account (used for internal state and triggers), and the Function App resource itself. This example uses a Consumption plan.

    bash
    az group create --name rg-myfunctionapp --location eastus

az storage account create \
  --name mystoragefunc001 \
  --resource-group rg-myfunctionapp \
  --sku Standard_LRS

az functionapp create \
  --resource-group rg-myfunctionapp \
  --consumption-plan-location eastus \
  --runtime dotnet \
  --functions-version 4 \
  --name my-function-app-001 \
  --storage-account mystoragefunc001

  4. Deploy your code

    Publish the local project directly to the Function App you just created. Core Tools packages and pushes it in one step.

    bash
    func azure functionapp publish my-function-app-001

  5. Verify the live endpoint

    The publish command prints the live HTTPS endpoint on success. Call it directly to confirm the deployment worked end to end.

    bash
    curl https://my-function-app-001.azurewebsites.net/api/HttpExample

  6. Wire up Application Insights

    If you haven't already, this is the point to connect the app to Application Insights — see the Application Insights + KQL tutorial so you have real telemetry from the very first deployment rather than adding it after something breaks.

Result: a working HTTP-triggered Function App deployed entirely from the command line, ready to extend with other trigger types (Blob, Queue, Timer, Event Grid) as your scenario grows.
