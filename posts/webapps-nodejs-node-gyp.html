Node.js Deployment Fails: node-gyp and Native Module Build Errors on Oryx

Node.js Oryx 6 min read
01SYMPTOM
02ENVIRONMENT
03DIAGNOSIS
04ROOT CAUSE
05FIX

01Symptom

Deployment fails during the build step with an error surfacing from node-gyp or a native dependency's install script, even though npm install works fine locally. The failure is specific to deployment via Oryx (ZipDeploy with build enabled, Local Git, or similar) rather than a pre-built artifact deployment.

02Environment

  • Node.js application on App Service Linux with a dependency that includes native C++ bindings (common in image processing, native crypto, or certain database driver packages)
  • Deploying via a method that triggers Oryx build (SCM_DO_BUILD_DURING_DEPLOYMENT=true, or default-enabled Local Git/Bitbucket)

03Diagnosis

Oryx pulls the Node.js runtime based on the preselected stack version for the build. If a dependency's install script requires node-gyp to compile a native binding, that compilation step itself needs Python available in the build environment — and depending on the exact build context, Python may not be present or correctly configured, causing the native build step to fail even though the rest of the npm install succeeds.

  • Check the build log for the specific package failing — it's typically a native dependency, not your own application code.
  • Confirm whether the same install succeeds in a clean local environment matching the target Node version, to rule out an unrelated dependency issue.
Common misdiagnosis: because "npm install works fine locally," this sometimes gets treated as an Oryx platform bug. The build environments genuinely differ — local development machines typically have a full native build toolchain and Python already available, which the Oryx build container may not provide in the same way.

04Root Cause

Native npm modules aren't just JavaScript — their install script invokes node-gyp, which compiles C/C++ source using Python as part of the toolchain. Oryx's build environment is optimized for typical Node.js application builds and may not include everything a native compilation step needs, so a dependency that "just works" with a full local toolchain can fail specifically inside the Oryx build context.

05Fix

  • Build locally and deploy the pre-built artifact instead of relying on Oryx to build it — run npm install and any build steps locally (or in a CI environment you control with the full toolchain), then ZipDeploy the result including node_modules.
  • If you need Oryx to build it, check whether the native dependency has a prebuilt binary distribution option that avoids compilation entirely — many popular native packages offer this as an alternative to compiling from source.
  • Consider whether the native dependency is actually necessary — a pure-JavaScript alternative avoids this entire class of problem if one exists with acceptable performance for your use case.
  • For unrelated `npm run build` compile failures (React/Angular/Vue/Next.js builds failing under Oryx), the same "build locally, deploy the output" approach applies — identify the specific failing library, and if it's a memory constraint rather than a missing toolchain, increase Node's --max-old-space-size or scale up the build environment.
Prevention tip: for any application with native dependencies, prefer building in a CI environment you control (GitHub Actions, Azure Pipelines) with an explicit, reproducible toolchain, and deploy the finished artifact — this removes Oryx's build environment as a variable entirely rather than hoping it matches what a native module needs.
