Setting Up an Event Grid-Based Blob Trigger, Start to Finish

Intermediate Event Grid 8 min read

This is the fix referenced in the blob trigger latency troubleshooting post on this site — moving a Blob trigger from polling to an Event Grid event subscription, so the function fires the moment a blob lands rather than on the next poll cycle.

Before you start
  • An existing blob-triggered Function (see the Blob trigger walkthrough on this site if you're starting from scratch)
  • A general-purpose v2 Storage Account — Event Grid subscriptions on Blob Storage require this account kind specifically

  1. Upgrade the Storage extension

    The Event Grid-based source requires Storage extension version 5.x or later. Update your extension bundle in host.json to a version range that includes it.

    host.json
    {
  "extensionBundle": {
    "id": "Microsoft.Azure.Functions.ExtensionBundle",
    "version": "[4.0.0, 5.0.0)"
  }
}

  2. Change the trigger source

    Update the binding to specify EventGrid as the source instead of the default polling behavior.

    function.json
    {
  "bindings": [
    {
      "name": "myBlob",
      "type": "blobTrigger",
      "direction": "in",
      "path": "uploads/{name}",
      "source": "EventGrid",
      "connection": "AzureWebJobsStorage"
    }
  ]
}

  3. Deploy the updated function

    Publish the change to your Function App. At this point the trigger definition is updated, but no events will arrive yet — the Event Grid subscription itself doesn't exist until the next step.

  4. Get the blob extension webhook URL and key

    In the portal, under your Function App → App keys, copy the blobs_extension system key. Build the webhook endpoint URL using this pattern:

    Endpoint URL pattern
    https://<function-app-name>.azurewebsites.net/runtime/webhooks/blobs?functionName=Host.Functions.<FunctionName>&code=<blobs_extension_key>

  5. Create the Event Grid event subscription

    On the Storage Account, go to Events → + Event Subscription. Set Endpoint Type to Web Hook, paste the URL from the previous step, and filter Event Types to Blob Created.

  6. Scope the subscription with filters

    Under the Filters tab, enable subject filtering and scope it to the specific container (and optionally a blob name prefix/suffix) you want to trigger on — this avoids firing on unrelated container activity.

    Example filter
    Subject Begins With: /blobServices/default/containers/uploads/blobs/
Subject Ends With:   .csv

  7. Verify end to end

    Upload a test blob and confirm the function fires within seconds rather than minutes. Check the storage account's Events → Event Subscriptions page to confirm delivery, and the function's own invocation logs to confirm execution.

Result: a blob trigger that fires on an actual event rather than a polling cycle — the fix for the latency issue covered in the companion troubleshooting post, and required outright if you're on the Flex Consumption plan.
