Setting Up Azure AD B2C Authentication for a Static Web App

Intermediate Azure AD B2C 8 min read

This builds a working custom authentication flow from scratch — the exact configuration that the auth redirect loop troubleshooting post on this site assumes you already have in place.

Before you start
  • An Azure AD B2C tenant (separate from your regular Azure AD tenant)
  • An existing Static Web App

  1. Register an application in Azure AD B2C

    In your B2C tenant, go to App registrations → New registration. Give it a name, and under Redirect URI, select "Web" and add your Static Web App's production callback URL: https://<your-app>.azurestaticapps.net/.auth/login/aadb2c/callback.

  2. Create a client secret

    Under Certificates & secrets, create a new client secret and copy its value immediately — it's only shown once. This is the value the redirect loop post warns about needing in App Service Configuration, not just the config file.

  3. Create or select a user flow

    Under User flows, create a Sign up and sign in flow if you don't already have one. Note its name (e.g. B2C_1_signupsignin) — you'll reference it in the SWA configuration.

  4. Configure staticwebapp.config.json

    Add the B2C provider configuration, referencing the app registration's client ID and the secret by setting name (not the raw value).

    staticwebapp.config.json
    {
  "auth": {
    "identityProviders": {
      "customOpenIdConnectProviders": {
        "aadb2c": {
          "registration": {
            "clientIdSettingName": "AADB2C_PROVIDER_CLIENT_ID",
            "clientCredential": {
              "clientSecretSettingName": "AADB2C_PROVIDER_CLIENT_SECRET"
            },
            "openIdConnectConfiguration": {
              "wellKnownOpenIdConfiguration": "https://<tenant>.b2clogin.com/<tenant>.onmicrosoft.com/B2C_1_signupsignin/v2.0/.well-known/openid-configuration"
            }
          },
          "login": {
            "nameClaimType": "name",
            "scopes": ["openid"]
          }
        }
      }
    }
  }
}

  5. Set the actual secret value in SWA Configuration

    In the Static Web App resource — not the config file — go to Settings → Configuration and add AADB2C_PROVIDER_CLIENT_ID and AADB2C_PROVIDER_CLIENT_SECRET with the real values from your app registration. This is the step the redirect loop post identifies as the most commonly missed.

  6. Test the flow end to end

    Navigate to /.auth/login/aadb2c on your deployed app in a fresh/incognito browser session and confirm you land back on an authenticated page rather than looping. If it loops, work through the redirect loop troubleshooting post — redirect URI mismatch and missing Configuration secrets are the two most common gaps.

Result: a working Azure AD B2C login flow wired into Static Web Apps, with the redirect URI and secret configuration in the two places SWA actually needs them.
