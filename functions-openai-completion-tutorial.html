Adding Azure OpenAI Text Completion to an Azure Function

Intermediate Azure OpenAI 7 min read

A common pattern is a Function that takes a request, calls Azure OpenAI for a completion, and returns the result — useful as a backend for a chat feature, a summarization endpoint, or as one tool in a larger agent setup like the MCP server tutorial on this site. This covers doing it with Managed Identity rather than an API key sitting in application settings.

Before you start
  • An Azure OpenAI resource with a model deployment (e.g. GPT-4o)
  • An existing HTTP-triggered Function App

  1. Enable a managed identity on the Function App

    Same pattern as the storage identity posts on this site — go to Identity and enable a system-assigned identity.

  2. Grant the identity access to Azure OpenAI

    On the Azure OpenAI resource, assign the Cognitive Services OpenAI User role to the Function App's identity, scoped to that resource.

    bash
    az role assignment create \
  --assignee <function-app-identity-principal-id> \
  --role "Cognitive Services OpenAI User" \
  --scope /subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.CognitiveServices/accounts/<openai-resource>

  3. Add the OpenAI endpoint as an app setting

    Store the resource endpoint (not a key) as configuration — this is safe to keep as a plain app setting since it's not a secret on its own.

    bash
    az functionapp config appsettings set \
  --name my-function-app \
  --resource-group rg-myapp \
  --settings AZURE_OPENAI_ENDPOINT="https://my-openai-resource.openai.azure.com/"

  4. Call Azure OpenAI using identity-based auth

    Use the Azure Identity SDK's credential type together with the OpenAI SDK, rather than passing an API key — the SDK obtains a token via the function's managed identity automatically.

    Python — identity-based client
    from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from openai import AzureOpenAI

credential = DefaultAzureCredential()
token_provider = get_bearer_token_provider(
    credential, "https://cognitiveservices.azure.com/.default"
)

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    azure_ad_token_provider=token_provider,
    api_version="2024-06-01",
)

  5. Wire it into an HTTP trigger

    Accept a prompt from the request body, call the completion endpoint, and return the result — straightforward once the identity-based client is set up.

    Python — handler
    response = client.chat.completions.create(
    model="gpt-4o-deployment-name",
    messages=[{"role": "user", "content": prompt}],
)
return response.choices[0].message.content

  6. Add timeout and error handling

    Model calls can be slower than typical function work — set an appropriate function timeout, and handle rate-limit or transient errors from the OpenAI endpoint explicitly rather than letting them surface as unhandled exceptions.

Result: a Function calling Azure OpenAI with no API key in configuration anywhere — consistent with the Managed Identity pattern used throughout the Security & Monitoring posts on this site, now applied to an AI integration instead of storage.
